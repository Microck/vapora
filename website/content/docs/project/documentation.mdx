## Local workflow

From the repository root:

```sh
cd website
npm ci
npm run dev
```

Edit MDX in `content/docs/` and navigation order in each folder's `meta.json`. Public screenshots are copied from tracked `docs/screenshots/` by the predev/prebuild asset script. The Vapora icon comes from `assets/vapora.svg`.

```sh
npm run verify
```

This checks TypeScript, renders every page, validates internal links and fragment targets, and exercises the exported search index with the real static search client. The lockfile pins the tested dependency graph. CI also builds and checks the site on documentation PRs.

## Writing conventions

The README stays a practical entry point, following kagi-cli's lowercase sections, centered mark, flat-square badges and runnable examples. The site separates learning, task guides, factual reference and explanation, following [Diátaxis](https://diataxis.fr/start-here/).

Keep defaults and flags aligned with `src/model.ts` and `src/cli.ts`. Verify exports against `src/analysis.ts` and formulas against `src/scoring.ts`. Document source dates, coverage and missing data next to the affected feature. Use illustrative IDs rather than claiming sample accounts are real. Label fixture screenshots. Keep existing release and verification reports as historical records rather than rewriting them into current claims.

## Design

The shell uses Steam-inspired navy `#171d25`, blue `#1b2838` and cyan `#66c0f4`. Olive accents use Vapora's actual app variables: `#4c5844`, `#3e4637`, `#d8ded3` and maize `#d8cc75` from `ui/style.css`. The site uses a forced dark theme, visible keyboard focus, responsive navigation and reduced-motion support. No Steam fonts or new remote assets are required.

## Build and host

```sh
npm ci
npm run verify
```

The public site is [vapora.micr.dev](https://vapora.micr.dev/), hosted on GitHub Pages. The documentation workflow verifies changes on pull requests and deploys the checked `website/out/` artifact from `main`. It can also be run manually through GitHub Actions. Deployment uses the `github-pages` environment and waits for the build to pass.

The export includes HTML, assets, a local search index and a 404 page. No Steam key, Python, Electron or Node server is needed by the deployed docs. Pages serves clean paths with trailing slashes, so `/docs/reference/cli/` resolves to its `index.html`. `/api/search` is an exported JSON file; searches run in the browser.

The custom domain uses the default domain-root configuration, without a Next.js `basePath`. GitHub Pages uses Actions as its publishing source and `vapora.micr.dev` as its custom domain. The DNS CNAME for `vapora` points to `microck.github.io`. HTTPS is enforced once GitHub has issued the domain certificate. The deployed site documents the local app; it does not host the Steam scanner.

# Vapora 2 contract

Vapora runs locally on Node.js 24 and uses TypeScript and Effect 4. The Python implementation stays on the remote `legacy` branch. The rewrite has one scan and report format. It does not read legacy checkpoints.

## Required behavior

- Distribute self-contained desktop downloads: a Windows NSIS installer and portable EXE, Linux AppImage and macOS DMG. Bundle Electron, runtime dependencies and the existing desktop/server/UI assets; do not require a separate Node.js install. Exclude local credentials, saved runs, development dependencies and test fixtures from the packaged app.
- Build desktop downloads on their native operating systems and test the packaged executable with a fresh data directory and the local Steam fixture before publishing. Keep published tags fixed, identify architecture in filenames, and disclose unsigned downloads. Attach installers only after all platform checks pass.
- The Windows portable EXE runs without installation and stores checkpoints, exports, settings and Electron session files in `Vapora-data` beside the original EXE, never in its temporary extraction directory. The folder must be writable. Moving the EXE together with `Vapora-data` preserves saved runs. `VAPORA_ROOT` explicitly overrides the data location for every desktop distribution. Native Windows CI launches both the installer and portable downloads and verifies portable data after moving and reopening them.
- Accept individual SteamID64, SteamID2, SteamID3, Steam community profile URLs, and vanity names. `/id/` URL segments always identify vanity names, including numeric names; `/profiles/` segments identify SteamID64. Reject other hosts, malformed IDs, and unsupported account types before scanning.
- Offer validated manual configuration and named saved profiles. Keep inner/community shortcuts in the CLI. In the GUI, Outputs: All / Report / Gephi selects the visible output files and never overwrites scan settings or limits which files are generated. Apply saves the default settings profile; saved settings include the private-profile policy. Put ranking defaults in a Ranking options dialog opened from scan parameters, separate from API-key setup.
- Scan public friendship networks breadth first to depth 1-5. A positive node cap limits admitted accounts; 0 disables the cap. Depth 1 includes the seed and its direct friends. Query admitted boundary nodes for analysis, without admitting nodes beyond a positive limit. Estimates use the same cap semantics.
- Offer an explicit Skip private profiles checkbox, unchecked by default. Check summaries before collecting a frontier account's own observations. With the policy enabled, retain known private accounts and incoming friendship evidence, but skip their friend-list, ban, group and game requests. Persist skipped statuses and the policy for resume and saved profiles. Missing summary visibility is unavailable, not proof of privacy. A public profile with a private friend list remains eligible for other enabled observations. A private seed produces a completed skipped result.
- Distinguish private/unavailable friend lists from empty public lists. Keep admitted profiles even when private. A bad API key, exhausted retry, or malformed provider payload must fail visibly.
- A positive Requests/min value paces every API request; 0 removes application pacing. Both modes retain bounded retries, Retry-After handling and cancellation. Save and restore zero limits through the same settings schema, CLI and browser controls.
- Atomic file replacement retries Windows sharing/access contention for a bounded 1.55 seconds, without overwriting the last valid checkpoint in place. Permanent save failures expose the filesystem error code and a recovery action; keep the underlying error in diagnostic causes and remove failed temporary files. Verify real Windows file locks and a 500-account scan with concurrent saved-run reads.
- Save atomic checkpoints after completed scan units. Resume the exact frontier, settings, and seed without reprocessing completed units. Cancelled or failed runs remain resumable. A hard cap must not leave dangling graph edges.
- Verify API authority at the start of each scan or resume. Keep a returned-but-missing ban record distinct from a record that has not been requested.
- Diagnose damaged saved runs individually while continuing to list healthy runs and allowing new scans. Never repair or delete damaged files automatically.
- Fetch summary and ban information in batches of at most 100. Optional owned-game overlap and shared-group links must use real provider data and expose denied or unavailable access.
- Export canonical `scan.json`, `analysis.json`, `probable-friends.csv`, `gephi/nodes.csv`, `gephi/edges.csv`, and timestamped `run.log` under a unique run directory. Escape CSV fields correctly and prevent spreadsheet formulas in untrusted text fields.
- Offer an Obsidian vault ZIP from saved results without provider requests. Include an index and a Markdown note for every admitted profile and referenced friend, with stable Steam-ID filenames, properties and internal links for observed friendships. Preserve unknown/partial collection states, dated historical observations and warnings. Escape untrusted names and comments, include no credentials, and require no Obsidian plugin. Exporting must not rewrite the checkpoint. Reconstruct graph metrics and compress the vault off the server thread. Terminate its worker when the download connection closes, including during server shutdown. Include group and game collection states so disabled, private, skipped, unavailable and unknown signals remain distinct. Keep observed current names; dated history can name unobserved profile placeholders.
- User-facing labels, tooltips, errors, generated note text and documentation call historical data History or account history, without the provider's brand. Preserve original imported bytes, wire-format identifiers and provenance URLs unchanged.
- Compute degree, normalized betweenness, deterministic Louvain communities, and percentile-based hubs. Treat friendships as undirected; group links remain a distinct kind. Graph metrics use friendship edges, so group co-membership does not distort friendship centrality.
- Rank direct friends with configurable mutual, Jaccard, shared-group, and shared-game signals. Explain missing observations and graph truncation. Display friend and location estimates as heuristic scores, never calibrated real-world probabilities.

## Analysis limits

Steam profiles and friend lists can have different privacy settings. Unavailable observations do not count as known empty sets. Friendships outside the admitted graph can affect ranking signals but not graph metrics. Report coverage explicitly. Location fields are self-reported Steam country/state/city codes, not verified residence. Public group lookup may require publisher permissions. account history is a separate, dated source. Vapora requests only the selected account's fixed account history profile and history endpoints, never arbitrary URLs. Provider failures leave Steam scans usable.

Steam summaries retain each profile's full avatar URL in the current checkpoint. The target, recent runs, report heading and friend rows display that profile picture in square frames. Missing or failed images use the existing local placeholder. Editing the target clears the previous account's identity. An explicit successful lookup takes precedence over a matching saved run's identity, including failed runs with incomplete summaries. No avatar lookup or extra Steam requests run while typing.

Current checkpoints and settings profiles require the restored analysis controls, `skipPrivate`, nullable avatar, separate friend-list/ban observation dates, and VAC-count fields. Earlier local files remain untouched and are reported as invalid; start a fresh scan or explicitly save a new settings profile. There is no automatic migration.

### Formula contract

For a count x and reference population P, use:

`A(x) = 100 * (2 * min(1, x / max(1, 1.5 * meanTopN(P))) + 2 * min(1, x / max(1, max(P))) + min(1, x / B)) / 5`.

Defaults: Top N 5 and baseline B 50. Empty P has no index. Network P contains every known direct friend, including zero observed incoming counts and accounts outside the admitted graph. Incoming mutuals count appearances in other direct friends' observed lists. Keep undirected mutuals distinct. Unknown lists provide no observed edges but are never described as measured empty lists.

The optional combined index is `(wm*A(mutual) + 100*wf*Jfriends + 100*wg*Jgroups + 100*wa*Jgames) / sum(weights)`. Defaults are mutual 1 and other weights 0. Use bounded Jaccard for optional signals; retain raw overlap counts. Complete empty unions yield zero. Unknown comparisons contribute no observed support, with the configured denominator unchanged and availability visible. All-zero weights yield no index and sort observed incoming count. Preserve precision through sorting; round only for display. Break ties by Steam ID.

Friend-comment A uses only positive-count authors with friendship evidence anywhere in the supplied captures, including former friends. Nonfriend commenters and displayed zero rows never change that reference. Membership filters do not change the reference; date ranges do. Profile and ban metadata filters use source observation dates. Do not compute a second all-commenter index.

Keep network and friend-comment location evidence separate. Group only supplied country/city codes; missing-city records stay visible outside this calculation. Restore sum/product selection (default product), baseline 100. For city support s and total T, `L = 100 * (2*s/T + min(1,s/B_location)) / 3`. Product uses true zero-absorbing semantics. Use exact integer products and sums, bounded ratio conversion, and decimal-string exports. Zero total has no index or share. Expose contributor and zero-contributor counts, raw support, source population and coverage. Location fields and indices never establish real residence.

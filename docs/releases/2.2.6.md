# vapora 2.2.6

This patch release fixes issues found during automated and hands-on QA.

- Exported history reports can be imported again. Original captures are retained, repeated imports are deduplicated, and rankings are recomputed from validated observations rather than trusting exported scores. Empty and cross-account reports are rejected.
- Cancelled or superseded settings loads no longer overwrite newer edits or close a reopened dialog. Explicit profile selection takes precedence over startup defaults, and stale estimates are invalidated.
- A damaged optional default profile now produces a recoverable diagnostic instead of leaving a healthy app marked disconnected. The original file is preserved.
- Incomplete Steam groups and games responses remain unavailable rather than appearing as public empty lists. Partial observed game IDs are retained without claiming complete coverage.
- The packaged history helper recovers when Chromium starts without an initial page, using a bounded five-second fallback. Other startup errors still propagate.
- CLI commands reject extra operands before storage or network side effects. Installation examples and documentation now follow the current app version.

Native package tests use disposable local Steam and history fixtures. Fixture tests do not establish live-provider access or production-account behavior. History imports retain the documented 2 MB browser limit.

Windows downloads include an installer and a portable EXE. The portable app keeps data in `Vapora-data` beside the EXE and needs about 1 GB free in Windows TEMP, plus space for scan data. Move the EXE and data folder together. Downloads are unsigned and not notarized; verify them against `SHA256SUMS.txt`.
